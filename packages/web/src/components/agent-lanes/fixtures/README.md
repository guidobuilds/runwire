# Agent lanes metadata fixtures

The five session files project the prototype samples onto the frozen `LanesResponse`
contract. They contain no tool names, prompts, responses, tool I/O, or session titles.
Calls retain their original epoch timestamps as ISO strings. Agent labels become IDs;
missing tree parents/depths use the prototype defaults (`main`, depth 1).

These fixtures deliberately use the prototype's model windows and tiers. Production
responses obtain those configurable values from core's `lookupModelCatalog` instead.
Compaction/model-change marks (including `after`) and tool spawn IDs are retained;
turn marks are omitted. `spawnCallId` is null because the samples have no tool call IDs.
The contract cannot represent the number of unlinked agent-tool steps: subagent marks
therefore count linked spawn IDs, or at least one when the call kind is `agent`.

## Detection oracle

`expected-detections.json` was generated by executing the prototype's own `buildModel`
and `detect` functions with all three rules enabled and threshold 85, over the original
five sample JSON files. The extractor ran with Bun in a system temporary directory;
it was not added to the repository. The JSON retains the original finding text.

The S19 tests compare exact agent IDs, inclusive global zero-based `from`/`to` ranges,
and finding order. Text comparisons normalize only information discarded by the
contract: mechanical findings say “only mechanical tools” instead of listing tool
categories; failure findings omit the category suffix. Context text is unchanged.
The prototype uses transitive failure groups: consecutive failing calls must be at
most 10 local calls apart, not necessarily within 10 calls across the entire group.

## Renderer API notes

- `buildModel(response)` is pure and creates fresh data. Memoize it at the caller by
  response identity/session revision; caching only by session ID would stale live data.
- `cols` and each agent's `cols` are in global time order. `index` is the global
  zero-based call position; `local` is the zero-based position within that lane.
  `byId` and `children` preserve response agent order. `at` is epoch milliseconds.
- Context percentages use 0–100 (not 0–1); unknown context stays null. Marks are counts;
  events preserve before/after placement. Spawn connectors can have null targets.
- Viewport coordinates are relative to the lane plotting area (exclude name gutter).
  `zoom` factor > 1 zooms in; `pan` delta is in calls. `fit` reserves at least 12 slots.
  Buckets align to global indices, with inclusive ranges and first-call tie breaking.
  Apply bucketing per lane. Null-only context buckets stay null. `tickStep` accepts
  desired call spacing (for example `90 / ppc(view, width)`).
- Precompute indicator output and findings when session/options change, not per frame.
  Color tokens in the indicator registry are declarations for T4, not CSS definitions.
